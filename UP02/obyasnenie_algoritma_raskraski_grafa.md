# Подробное объяснение алгоритма раскраски графа для учебной практики

## Тема задания

**Условие:**  
Дисциплины — вершины графа, рёбра — конфликты, то есть пары дисциплин, которые нельзя поставить в одну смену. Нужно раскрасить граф в минимальное количество цветов, чтобы конфликтующие дисциплины имели разные цвета.

**Дополнительно:**  
Нужно минимизировать количество смен, в которых один преподаватель преподаёт несколько дисциплин.

**Алгоритм:**  
Жадная раскраска графа + локальная оптимизация.

---

# 1. Самая главная идея

Нужно составить расписание дисциплин по сменам.

Есть дисциплины:

```text
Математика
Физика
Информатика
История
Базы данных
```

Некоторые дисциплины нельзя ставить вместе в одну смену.

Например:

```text
Математика конфликтует с Физикой
Физика конфликтует с Информатикой
История конфликтует с Базами данных
```

Это значит:

- Математика и Физика должны быть в разных сменах.
- Физика и Информатика должны быть в разных сменах.
- История и Базы данных должны быть в разных сменах.

В теории графов это записывается так:

- дисциплина — это **вершина графа**;
- конфликт между дисциплинами — это **ребро графа**;
- смена — это **цвет вершины**.

То есть в задаче говорится “раскрасить граф”, но по смыслу это значит:

> Назначить каждой дисциплине номер смены.

---

# 2. Что такое граф в этом задании

## Вершины графа

Вершина — это дисциплина.

Например:

```text
A = Математика
B = Физика
C = Информатика
D = История
```

Каждая дисциплина становится отдельной вершиной графа.

---

## Рёбра графа

Ребро — это конфликт между двумя дисциплинами.

Например:

```text
A — B
B — C
```

Это значит:

```text
Математика конфликтует с Физикой
Физика конфликтует с Информатикой
```

Если между двумя дисциплинами есть ребро, их нельзя поставить в одну смену.

---

# 3. Что значит “раскрасить граф”

Раскрасить граф — значит назначить каждой вершине цвет.

Но в этой задаче цвет — это не настоящий цвет, а номер смены.

Например:

```text
Математика   → цвет 1 → смена 1
Физика       → цвет 2 → смена 2
Информатика  → цвет 1 → смена 1
История      → цвет 1 → смена 1
```

Если две дисциплины конфликтуют, они должны иметь разные цвета.

Например:

```text
Математика — Физика
```

Если Математика стоит в смене 1, то Физику нельзя поставить в смену 1. Её нужно поставить в смену 2, 3 и так далее.

---

# 4. Главная цель алгоритма

Алгоритм должен сделать три вещи:

1. Поставить конфликтующие дисциплины в разные смены.
2. Использовать как можно меньше смен.
3. По возможности уменьшить ситуации, когда один преподаватель несколько раз попадает в одну смену.

То есть алгоритм сначала делает расписание **корректным**, а потом пытается сделать его **лучше**.

---

# 5. Что подаётся на вход алгоритма

В алгоритм подаются две основные структуры:

```text
vertices
edges
```

---

## `vertices`

`vertices` — это список дисциплин.

Например:

```text
vertices = [
    "Математика",
    "Физика",
    "Информатика",
    "История"
]
```

Это все дисциплины, которые надо распределить по сменам.

---

## `edges`

`edges` — это список конфликтов.

Например:

```text
edges = [
    ("Математика", "Физика"),
    ("Физика", "Информатика")
]
```

Это значит:

- Математика конфликтует с Физикой.
- Физика конфликтует с Информатикой.

---

# 6. Секция 1: построение графа

Первая часть алгоритма строит граф конфликтов.

Задача этой секции — понять, какая дисциплина с какими дисциплинами конфликтует.

---

## Шаг 1. Создаётся список смежности

В алгоритме есть действие:

```text
adj[v] = {} для всех v ∈ vertices
```

`adj` — это список смежности.

Проще говоря:

> Для каждой дисциплины создаётся список дисциплин, с которыми она конфликтует.

Например, если есть дисциплины:

```text
Математика
Физика
Информатика
История
```

То сначала создаётся пустой список конфликтов:

```text
adj[Математика] = {}
adj[Физика] = {}
adj[Информатика] = {}
adj[История] = {}
```

Пока конфликтов ещё нет, списки пустые.

---

## Шаг 2. Перебираются все конфликты

В алгоритме есть действие:

```text
Для каждого (u, v) ∈ edges
```

Это значит:

> Берём каждый конфликт из списка конфликтов.

Например, есть конфликт:

```text
("Математика", "Физика")
```

Здесь:

```text
u = Математика
v = Физика
```

---

## Шаг 3. Проверяется, что дисциплина не конфликтует сама с собой

В алгоритме есть проверка:

```text
u ≠ v ?
```

Она нужна, чтобы не было бессмысленного конфликта вида:

```text
("Математика", "Математика")
```

Дисциплина не должна конфликтовать сама с собой.

Если `u` и `v` разные, конфликт считается нормальным.

---

## Шаг 4. Конфликт добавляется в обе стороны

В алгоритме есть действие:

```text
adj[u] += v
adj[v] += u
```

Это значит:

> Если Математика конфликтует с Физикой, то Физика тоже конфликтует с Математикой.

То есть граф неориентированный.

Пример:

```text
edges = [
    ("Математика", "Физика")
]
```

После обработки получится:

```text
adj[Математика] = {Физика}
adj[Физика] = {Математика}
```

---

## Что получилось после первой секции

После построения графа алгоритм знает, кто с кем конфликтует.

Например:

```text
Математика: Физика
Физика: Математика, Информатика
Информатика: Физика
История: нет конфликтов
```

Это ещё не расписание.  
Это только подготовка данных для раскраски.

---

# 7. Секция 2: жадная раскраска Welsh-Powell

Вторая часть алгоритма — это основная раскраска графа.

Здесь каждой дисциплине назначается смена.

---

## Что такое Welsh-Powell

Welsh-Powell — это жадный алгоритм раскраски графа.

Он работает так:

> Сначала обрабатываются самые конфликтные дисциплины.

Самые конфликтные дисциплины — это те, у которых больше всего рёбер, то есть больше всего конфликтов.

Например:

```text
Физика конфликтует с 5 дисциплинами
История конфликтует с 1 дисциплиной
```

Физика сложнее для расписания, поэтому её лучше обработать раньше.

---

## Что такое степень вершины

Степень вершины — это количество её конфликтов.

Например:

```text
Математика конфликтует с Физикой и Информатикой
```

Значит, у Математики степень 2.

Другой пример:

```text
Физика конфликтует с Математикой, Информатикой и Историей
```

Значит, у Физики степень 3.

---

## Шаг 1. Сортировка дисциплин

В алгоритме есть действие:

```text
order = сортировка vertices по (−степень, имя)
```

Это значит:

> Сначала идут дисциплины с самым большим количеством конфликтов.

Символ `−степень` означает сортировку по убыванию.

То есть:

```text
сначала степень 5
потом степень 4
потом степень 3
потом степень 2
потом степень 1
потом степень 0
```

Если у двух дисциплин одинаковая степень, можно дополнительно сортировать по имени. Это нужно, чтобы порядок был стабильным и понятным.

---

## Шаг 2. Создаётся словарь цветов

В алгоритме есть действие:

```text
colors = {}
```

`colors` — это словарь, где хранится назначенная смена для каждой дисциплины.

Например:

```text
colors[Математика] = 1
colors[Физика] = 2
colors[История] = 1
```

То есть:

```text
дисциплина → номер смены
```

---

## Шаг 3. Перебор дисциплин

В алгоритме есть действие:

```text
Для каждой v ∈ order
```

Это значит:

> Берём каждую дисциплину в отсортированном порядке.

Например:

```text
1. Физика
2. Математика
3. Информатика
4. История
```

---

## Шаг 4. Поиск запрещённых смен

В алгоритме есть действие:

```text
forbidden = {colors[u] | u ∈ adj[v], u ∈ colors}
```

Сложно выглядит, но смысл простой:

> Смотрим, в каких сменах уже стоят дисциплины, конфликтующие с текущей дисциплиной.

Эти смены становятся запрещёнными.

Например, надо поставить Физику.

Физика конфликтует с Математикой и Информатикой.

Допустим:

```text
Математика уже стоит в смене 1
Информатика уже стоит в смене 2
```

Тогда для Физики запрещены смены:

```text
forbidden = {1, 2}
```

Физику нельзя поставить ни в смену 1, ни в смену 2.

---

## Шаг 5. Алгоритм начинает с первой смены

В алгоритме есть действие:

```text
color = 1
```

Это значит:

> Сначала алгоритм пробует поставить дисциплину в смену 1.

---

## Шаг 6. Проверяется, запрещена ли смена

В алгоритме есть проверка:

```text
color ∈ forbidden ?
```

Это значит:

> Текущая смена запрещена или нет?

Если смена запрещена, дисциплину туда ставить нельзя.

Например:

```text
color = 1
forbidden = {1, 2}
```

Смена 1 запрещена.

---

## Шаг 7. Если смена запрещена, пробуется следующая

В алгоритме есть действие:

```text
color += 1
```

Это значит:

> Пробуем следующую смену.

Например:

```text
было color = 1
стало color = 2
```

Если смена 2 тоже запрещена, алгоритм пробует смену 3.

---

## Шаг 8. Назначение смены

Когда алгоритм находит первую разрешённую смену, выполняется:

```text
colors[v] = color
```

Например:

```text
colors[Физика] = 3
```

Это значит:

```text
Физика поставлена в смену 3
```

---

# 8. Пример жадной раскраски руками

Пусть есть дисциплины:

```text
A = Математика
B = Физика
C = Информатика
D = История
```

Конфликты:

```text
A конфликтует с B
B конфликтует с C
A конфликтует с C
```

То есть A, B и C все конфликтуют друг с другом.  
D ни с кем не конфликтует.

---

## Шаг 1. Берём A

У A пока нет раскрашенных соседей.

Запрещённых смен нет:

```text
forbidden = {}
```

Назначаем первую смену:

```text
A = смена 1
```

---

## Шаг 2. Берём B

B конфликтует с A.

A уже стоит в смене 1.

Значит:

```text
forbidden = {1}
```

Смена 1 запрещена.

Пробуем смену 2.

```text
B = смена 2
```

---

## Шаг 3. Берём C

C конфликтует с A и B.

A стоит в смене 1.  
B стоит в смене 2.

Значит:

```text
forbidden = {1, 2}
```

Смена 1 запрещена.  
Смена 2 запрещена.

Пробуем смену 3.

```text
C = смена 3
```

---

## Шаг 4. Берём D

D ни с кем не конфликтует.

Запрещённых смен нет.

```text
forbidden = {}
```

Её можно поставить в смену 1.

```text
D = смена 1
```

---

## Итог

```text
Смена 1: A, D
Смена 2: B
Смена 3: C
```

В обычных названиях:

```text
Смена 1: Математика, История
Смена 2: Физика
Смена 3: Информатика
```

Почему Математика и История могут быть вместе?

Потому что между ними нет конфликта.

---

# 9. Почему алгоритм называется жадным

Алгоритм называется жадным, потому что он каждый раз выбирает первый подходящий вариант.

Он не перебирает все возможные расписания.

Он делает проще:

```text
Можно поставить в смену 1? Ставлю.
Нельзя? Пробую смену 2.
Нельзя? Пробую смену 3.
```

То есть он выбирает первую свободную смену.

---

# 10. Важный момент про минимальность

В задании сказано, что нужно минимизировать количество цветов, то есть смен.

Но важно понимать:

> Жадный алгоритм не всегда гарантирует идеальный математический минимум для любого графа.

Почему?

Потому что задача минимальной раскраски графа в общем случае сложная.  
Чтобы точно найти минимум, иногда нужно перебрать очень много вариантов.

Поэтому используется практический подход:

1. Сначала строится хорошее начальное расписание алгоритмом Welsh-Powell.
2. Потом это расписание улучшается локальной оптимизацией.

На защите можно сказать так:

> Жадная раскраска Welsh-Powell не всегда гарантирует глобальный минимум для любого графа, но она быстро строит корректную раскраску. После этого локальная оптимизация пытается уменьшить количество смен.

Это честный и правильный ответ.

---

# 11. Секция 3: локальная оптимизация количества смен

После жадной раскраски может получиться расписание, где используется слишком много смен.

Например:

```text
Смена 1: Математика, История
Смена 2: Физика
Смена 3: Информатика
Смена 4: Биология
```

Алгоритм думает:

> Можно ли убрать последнюю смену?

То есть можно ли Биологию из смены 4 перенести в смену 1, 2 или 3?

Если можно, смена 4 исчезнет.

---

## Шаг 1. Запускается цикл улучшения

В алгоритме есть переменная:

```text
есть_улучшения = True
```

Это значит:

> Пока алгоритм находит улучшения, он будет продолжать оптимизацию.

---

## Шаг 2. В начале попытки улучшение сбрасывается

В алгоритме есть действие:

```text
есть_улучшения = False
```

Это значит:

> Пока что улучшений не найдено.

Если потом алгоритм найдёт улучшение, он снова поставит `True`.

---

## Шаг 3. Определяется последняя смена

В алгоритме есть действие:

```text
max_color = max(colors.values())
```

`max_color` — это номер последней использованной смены.

Например:

```text
colors = {
    Математика: 1,
    Физика: 2,
    Информатика: 3,
    Биология: 4
}
```

Тогда:

```text
max_color = 4
```

Значит, сейчас используется 4 смены.

---

## Шаг 4. Ищутся дисциплины из последней смены

В алгоритме есть проверка:

```text
colors[v] = max_color ?
```

Это значит:

> Эта дисциплина стоит в последней смене?

Например:

```text
Биология = смена 4
max_color = 4
```

Значит, Биология находится в последней смене.  
Алгоритм попробует перенести её раньше.

---

## Шаг 5. Снова считаются запрещённые смены

В алгоритме есть действие:

```text
forbidden = {colors[u] | u ∈ adj[v]}
```

Смысл тот же:

> Нельзя перенести дисциплину в смену, где уже стоит конфликтующая с ней дисциплина.

Например:

```text
Биология конфликтует с Физикой
Физика стоит в смене 2
```

Тогда:

```text
forbidden = {2}
```

Биологию нельзя поставить в смену 2.

---

## Шаг 6. Пробуются более ранние смены

В алгоритме есть цикл:

```text
Для c от 1 до max_color − 1
```

Если `max_color = 4`, алгоритм пробует:

```text
1, 2, 3
```

Он не пробует смену 4, потому что дисциплина уже там стоит.  
Цель — убрать последнюю смену.

---

## Шаг 7. Если смена разрешена, дисциплина переносится

Если проверка показывает:

```text
c ∉ forbidden
```

то дисциплину можно поставить в эту смену.

Выполняется:

```text
colors[v] = c
```

Например:

```text
Биология была в смене 4
Биология стала в смене 1
```

---

## Шаг 8. Проверяется, освободилась ли последняя смена

В алгоритме есть проверка:

```text
max_color ∉ colors.values() ?
```

Это значит:

> Остались ли дисциплины в последней смене?

Если нет, значит последняя смена стала пустой.

Было:

```text
Смена 1: Математика
Смена 2: Физика
Смена 3: Информатика
Смена 4: Биология
```

Стало:

```text
Смена 1: Математика, Биология
Смена 2: Физика
Смена 3: Информатика
```

Смена 4 исчезла.

Количество смен уменьшилось.

---

## Шаг 9. Если улучшение найдено, цикл повторяется

Если удалось освободить последнюю смену, выполняется:

```text
есть_улучшения = True
```

Это значит:

> Расписание улучшилось. Надо попробовать улучшить его ещё раз.

Возможно, теперь получится убрать ещё одну смену.

---

# 12. Зачем нужна локальная оптимизация

Жадная раскраска быстро строит расписание, но иногда делает не самый лучший вариант.

Локальная оптимизация нужна, чтобы проверить:

> А нельзя ли кого-нибудь передвинуть и уменьшить количество смен?

Простая аналогия:

Ты разложил вещи по четырём коробкам.  
Потом посмотрел и понял, что вещи из четвёртой коробки можно разложить по первым трём.  
Тогда четвёртая коробка больше не нужна.

Так же и здесь:

- коробки — это смены;
- вещи — это дисциплины;
- нельзя класть вместе конфликтующие дисциплины.

# 13. Секция 3.2: минимизация конфликтов преподавателей

Это дополнительное условие задания.

Задание говорит:

> Минимизируйте количество смен, в которых преподаёт один преподаватель.

Смысл такой:

Даже если дисциплины не конфликтуют по графу, может получиться неудобная ситуация.

Например:

```text
Смена 1:
Математика — Иванов
Физика — Иванов
История — Петров
```

Формально, если Математика и Физика не соединены ребром, они могут быть в одной смене.

Но преподаватель Иванов встречается в этой смене два раза.

Это нежелательно.

Поэтому алгоритм пытается уменьшить такие ситуации.

# 14. Функция `teacher_conflicts`

В алгоритме есть функция:

```text
teacher_conflicts(colors)
```

Она считает штраф за преподавателей.

Проще:

> Она считает, сколько раз один и тот же преподаватель лишний раз встречается внутри одной смены.

---

## Пример 1

```text
Смена 1:
Математика — Иванов
Физика — Иванов
История — Петров
```

Преподаватели в смене:

```text
Иванов, Иванов, Петров
```

Иванов встречается 2 раза.

Один раз — нормально.  
Второй раз — лишний.

Значит, штраф:

```text
2 - 1 = 1
```

---

## Пример 2

```text
Смена 2:
Биология — Сидоров
Химия — Сидоров
География — Сидоров
```

Сидоров встречается 3 раза.

Один раз — нормально.  
Ещё два раза — лишние.

Значит, штраф:

```text
3 - 1 = 2
```

---

## Общая логика функции

Функция делает так:

```text
для каждой смены:
    собрать всех преподавателей этой смены
    для каждого преподавателя:
        если он встречается больше одного раза:
            добавить count - 1 к штрафу
```

Например:

```text
если преподаватель встретился 1 раз → штраф 0
если преподаватель встретился 2 раза → штраф 1
если преподаватель встретился 3 раза → штраф 2
```

---

# 15. Как алгоритм уменьшает конфликты преподавателей

Алгоритм пробует переносить дисциплины между сменами.

Но есть важное правило:

> Нельзя улучшать преподавателей так, чтобы сломать основное ограничение графа.

То есть дисциплину нельзя перенести в смену, где уже есть конфликтующая с ней дисциплина.

---

## Шаг 1. Запоминается старая смена

В алгоритме есть действие:

```text
old_c = colors[v]
```

Это значит:

> Запоминаем, в какой смене дисциплина была до переноса.

Например:

```text
Математика была в смене 1
old_c = 1
```

---

## Шаг 2. Считается старый штраф

В алгоритме есть действие:

```text
old_cost = teacher_conflicts(colors)
```

Это значит:

> Считаем, сколько сейчас конфликтов преподавателей.

Например:

```text
old_cost = 3
```

Это значит, что сейчас есть 3 лишних совпадения преподавателей.

---

## Шаг 3. Считаются запрещённые смены

В алгоритме снова есть действие:

```text
forbidden = {colors[u] | u ∈ adj[v]}
```

Это нужно, чтобы не поставить дисциплину туда, где уже есть конфликтующая дисциплина.

---

## Шаг 4. Пробуются все смены

В алгоритме есть цикл:

```text
Для c от 1 до max_color
```

Если всего 3 смены, алгоритм пробует:

```text
1, 2, 3
```

---

## Шаг 5. Проверяется, можно ли переносить

В алгоритме есть проверка:

```text
c = old_c ИЛИ c ∈ forbidden ?
```

Это значит:

- если `c = old_c`, это та же самая смена, переносить бессмысленно;
- если `c ∈ forbidden`, в этой смене есть конфликтующая дисциплина, туда нельзя.

---

## Шаг 6. Временный перенос

Если смена подходит, алгоритм временно переносит дисциплину:

```text
colors[v] = c
```

---

## Шаг 7. Проверка результата

После переноса алгоритм считает новый штраф:

```text
teacher_conflicts(colors)
```

И сравнивает:

```text
teacher_conflicts(colors) < old_cost ?
```

Если стало меньше, перенос оставляют.

Например:

```text
было old_cost = 3
стало new_cost = 2
```

Значит, стало лучше.

---

## Шаг 8. Откат, если стало не лучше

Если после переноса штраф не уменьшился, алгоритм возвращает дисциплину обратно:

```text
colors[v] = old_c
```

Например:

```text
Математика была в смене 1
Попробовали поставить в смену 2
Стало не лучше
Вернули в смену 1
```

---

# 16. Секция 4: формирование расписания

После всех оптимизаций нужно получить итоговое расписание.

В алгоритме создаётся структура:

```text
schedule = {}
```

`schedule` — это готовое расписание по сменам.

---

## Шаг 1. Перебираются все дисциплины

В алгоритме есть действие:

```text
Для каждой v ∈ vertices
```

То есть берём каждую дисциплину.

---

## Шаг 2. Дисциплина добавляется в свою смену

В алгоритме есть действие:

```text
schedule[colors[v]] += v
```

Это значит:

> Посмотреть, какой цвет у дисциплины, и добавить её в соответствующую смену.

Например:

```text
colors[Математика] = 1
colors[Физика] = 2
colors[История] = 1
```

Тогда получится:

```text
Смена 1: Математика, История
Смена 2: Физика
```

---

## Шаг 3. Вывод результата

В конце алгоритм выводит:

```text
num_colors, colors, schedule
```

---

## `num_colors`

`num_colors` — это количество использованных смен.

Например:

```text
num_colors = 3
```

Это значит, что расписание использует 3 смены.

---

## `colors`

`colors` показывает, какая дисциплина в какой смене.

Например:

```text
Математика  → 1
Физика      → 2
История     → 1
Информатика → 3
```

---

## `schedule`

`schedule` — это расписание в более удобном виде.

Например:

```text
Смена 1: Математика, История
Смена 2: Физика
Смена 3: Информатика
```

---

# 17. Полная логика алгоритма простыми словами

Алгоритм работает так:

1. Получает список дисциплин.
2. Получает список конфликтов между дисциплинами.
3. Строит граф конфликтов.
4. Для каждой дисциплины запоминает, с кем она конфликтует.
5. Сортирует дисциплины по количеству конфликтов.
6. Сначала обрабатывает самые конфликтные дисциплины.
7. Для каждой дисциплины смотрит, какие смены запрещены.
8. Выбирает первую доступную смену.
9. Получает первичное расписание.
10. Пытается уменьшить количество смен.
11. Для этого пробует перенести дисциплины из последней смены в более ранние.
12. Если последняя смена освобождается, количество смен уменьшается.
13. Потом считает конфликты преподавателей.
14. Пробует переносить дисциплины между сменами, чтобы уменьшить эти конфликты.
15. В конце формирует итоговое расписание.

# 19. Что такое `forbidden`

`forbidden` — это список запрещённых смен для текущей дисциплины.

В него попадают смены, где уже стоят дисциплины, конфликтующие с текущей.

Пример:

```text
Физика конфликтует с Математикой.
Математика уже стоит в смене 1.
Значит, для Физики смена 1 запрещена.
```

Тогда:

```text
forbidden = {1}
```

Физику нельзя поставить в смену 1.

---

# 20. Почему сортируем по степени

Степень вершины — это количество конфликтов дисциплины.

Чем больше конфликтов, тем сложнее поставить дисциплину в расписание.

Поэтому алгоритм сначала берёт самые сложные дисциплины.

Пример:

```text
Физика конфликтует с 5 дисциплинами
История конфликтует с 1 дисциплиной
```

Лучше сначала поставить Физику, потому что для неё меньше свободных вариантов.

---

# 21. Почему это жадный алгоритм

Алгоритм жадный, потому что он выбирает первую доступную смену.

Он не перебирает все варианты.

Он действует так:

```text
Пробую смену 1.
Если можно — ставлю.
Если нельзя — пробую смену 2.
Если нельзя — пробую смену 3.
```

То есть он принимает локально лучшее решение прямо сейчас.

---

# 22. Гарантирует ли алгоритм абсолютный минимум?

Нет, не всегда.

Жадная раскраска не всегда гарантирует глобальный минимум для любого графа.

Но она:

- быстро работает;
- строит корректное расписание;
- хорошо подходит для практической задачи;
- улучшается локальной оптимизацией.

На защите лучше сказать так:

> Для произвольного графа жадный алгоритм не всегда гарантирует абсолютный минимум цветов, потому что задача минимальной раскраски является сложной. Но Welsh-Powell даёт хорошее начальное решение, а локальная оптимизация пытается уменьшить количество смен.

---

# 23. Простая аналогия

Представь, что есть люди, которых надо рассадить по комнатам.

- Люди — это дисциплины.
- Комнаты — это смены.
- Если два человека поссорились, их нельзя сажать в одну комнату.
- Ссора — это ребро графа.
- Номер комнаты — это цвет.

Алгоритм делает так:

1. Сначала записывает, кто с кем поссорился.
2. Потом берёт самых конфликтных людей.
3. Каждого сажает в первую комнату, где нет его врагов.
4. Потом смотрит, можно ли освободить последнюю комнату.
5. Потом проверяет, нет ли неудобств с преподавателями.
6. В конце выдаёт список, кто в какой комнате.

В задаче вместо людей — дисциплины.  
Вместо комнат — смены.

# 24. Готовое объяснение для защиты

Можно выучить этот текст почти дословно.

```text
Мой алгоритм решает задачу составления расписания через раскраску графа. Сначала каждая дисциплина представляется вершиной графа. Если две дисциплины нельзя поставить в одну смену, между ними проводится ребро. Таким образом, получается граф конфликтов.

Цвет вершины означает номер смены. Поэтому задача раскраски графа означает распределение дисциплин по сменам. Если две вершины соединены ребром, они обязательно должны иметь разные цвета, то есть находиться в разных сменах.

Сначала алгоритм строит список смежности. Для каждой дисциплины сохраняется список дисциплин, с которыми она конфликтует. Затем применяется жадная раскраска Welsh-Powell. Дисциплины сортируются по убыванию количества конфликтов, чтобы сначала обработать самые сложные дисциплины. Для каждой дисциплины алгоритм смотрит, какие смены уже заняты её конфликтующими соседями, и выбирает первую доступную смену.

После первичной раскраски выполняется локальная оптимизация. Она пытается перенести дисциплины из последней смены в более ранние смены, если это не нарушает конфликтов. Если последняя смена освобождается, количество смен уменьшается.

Дополнительно алгоритм учитывает преподавателей. Для этого считается штраф: если один преподаватель встречается в одной смене больше одного раза, это считается конфликтом. Алгоритм пробует переносить дисциплины между сменами так, чтобы уменьшить этот штраф, но не нарушить основные ограничения графа.

В результате получается расписание, где конфликтующие дисциплины находятся в разных сменах, количество смен по возможности уменьшено, а расписание дополнительно оптимизировано по преподавателям.
```
